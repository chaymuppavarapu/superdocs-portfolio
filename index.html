DocTask

Evidence-grounded project intelligence system

What I built

DocTask transforms scattered project documents—plans, sprint updates, milestone notes, and follow-ups—into structured, traceable, and reviewable project knowledge. The system treats documents as the source of truth, extracting structured facts, detecting contradictions across sources, and preserving complete evidence chains so that every conclusion in the final report can be traced back to the original material.

Core workflow

Ingestion → Chunking → Embedding → Retrieval → Extraction → Normalization → Conflict detection → Human review → Draft report

Key capabilities

Semantic retrieval

Project-scoped vector search over indexed chunks using local embeddings, retrieving only relevant evidence instead of the full corpus.

Structured extraction

Groq-backed agent returns strict JSON facts with subject, type, value, temporal status, source document, and supporting evidence.

Conflict detection

Contradictory values across sources are surfaced for review rather than silently merged. Distinguishes contradiction from historical change.

Incremental updates

New documents trigger targeted re-extraction. Unaffected facts remain intact, preserving previously accepted decisions.

Audit trail

Every change is recorded with old value, new value, source, review status, and timestamp. Complete evidence chain from report to original document.

Crash recovery

Completed stages persist to PostgreSQL. Interrupted runs resume from the incomplete stage rather than restarting from scratch.

Growth Machine

Evidence-driven outbound research & personalization system

What I built

An evidence-driven growth machine for a narrow audience: B2B SaaS documentation and support teams with public evidence of multilingual, HTML/help-content, template-driven, or other document-heavy workflows.

The machine ingests public company evidence, validates the inputs, detects workflow signals, forms a grounded pain hypothesis, maps only supported SuperDocs capabilities, scores the opportunity, and produces a personalized research/outreach artifact for human review.

Core workflow

Public evidence → Validation → Workflow inference → Pain hypothesis → Capability mapping → Qualification → Personalization → Human review → Measurement

Key decisions

Narrow audience

Deliberately scoped to B2B SaaS documentation and support teams rather than building a generic lead-generation system.

Evidence foundation

Every qualification decision is grounded in public evidence. The system separates what evidence actually shows from inferred hypotheses.

Stops before outreach

The primary channel is outbound research and personalization, but the system stops before sending any outreach.

What was cut

Automated outreach, private contact enrichment, unrestricted lead scraping, and unsupported product claims were intentionally excluded.

Qualification signals

HTML/help-center workflows Document editing & revision Repetitive document processes Template-driven generation Localization & multilingual API document processing

Measurement & validation

The system records discovery count, evidence coverage, qualification rate, fit bands, input fingerprint, and timestamp. Two fresh development runs were executed against different evidence batches. Both produced evidence-backed target records, fit scores, workflow hypotheses, matched capabilities, and personalized artifacts without requiring a code change between runs.

Human loop

The output is intentionally a research artifact, not an autonomous sales action. A human must verify: evidence, workflow interpretation, qualification, product-fit claims, personalization, and whether outreach is appropriate. The application cannot send outreach.

Honest limitations

Public evidence is a signal, not inside information. A public feature or workflow does not prove that the company has the hypothesized pain. Workflow inference can be wrong, evidence can become stale, and personalization can still require refinement.

The next meaningful metric would be the percentage of qualified artifacts that a human reviewer considers sufficiently specific and credible to use.

Design principle

Evidence before inference. Inference before qualification. Qualification before personalization. Human review before action.
